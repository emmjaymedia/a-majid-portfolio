Design & operations

Why separate queues?

Payment deadlines and onboarding retries create different load patterns. Each workflow has its own durable queue, exact topic subscription and dead-message route, so one backlog can be investigated without interrupting the other.

What happens during an outage?

The broker-backed lab stores the event before replying, retries the publish with the same correlation ID and acknowledges processing after the outcome is saved. The public simulation illustrates these outcomes locally.

What would I validate before a rollout?

Check queue subscriptions and bindings, test one retry and one rejection, compare latency and spool depth, and exercise backup restore. The repository includes a SEMP provisioning script, Kubernetes deployment resources and an OKE handover runbook.

Metrics cover the latest 100 events. Rejections and pending events appear separately from the completion latency measure.
